# 视频生成镜头表

2026-10-18：默认使用[统一工作台](unified-workspace.md)的“生成执行”视图，与分镜图册共用镜头数据。schema_version 2批次源只保存镜号和执行配置，时间、参考缩略图及提示词由构建器派生；下文完整信息要求适用于派生执行包，不要求在批次源重复填写。旧schema_version 1历史计划仍可验证。

保持镜头表一份执行入口：一个批次可含多个镜头，一个镜头也可因失败拆分成多个任务；保存与原镜头ID的映射。剧情顺序和提交顺序可以不同。

每批最低信息：批次ID、镜头ID及覆盖范围、成片时长、请求时长、头尾余量、入口/结束状态、段内节拍与切镜、参考路径和用途、完整提示词、声音、不能改变的状态、安全剪点、失败拆法。日历等剪辑插镜标明 `edit_existing_image`，不虚构模型任务。

生成回填最低信息：`status`（prepared/submitted/running/failed/candidate/accepted；尚未执行的批次计划保持planned，runs留空）、执行工具、模型版本、任务ID、真实输出路径、实际时长、视觉/声音问题、采用决定、剪辑in/out。没有值就空缺并说明待做，不用示例任务ID填充。小范围需求不强制建数据库或额外系统。

参考必须标“身份/空间/结构/动作/终态”，不是排列全部现图当首帧。记录素材版本；后续换图不覆盖已提交任务的输入记录。人类阅读顺序为批次总览→本批参考缩略图→节拍/约束→执行与结果。

合并原则：相同空间与接触因果链优先；机位变化可写明确切镜。微观尺度、镜中虚拟主体、精确文字等建议独立处理时，说明具体风险，不宣称模型绝对不能合并。超过现场核实的单次上限必须拆分，不能通过漏动作/吞对白伪装满足。

2026-10-18作者修订：本项目以尽量减少调用、每次尽量用满30秒为先。衣柜、贴窗飞行、开关帘仍合入多镜批次，复杂性只决定验收重点。已有日历图用剪辑插镜；不因它插在故事中间就强制切开生成。可将独立尾镜放入前批余量空间，写明硬切和声音隔离，逐镜给原片入出点→成片入出点。先整批生成，真实失败后再局部补拍；不预先增加短镜试验批次。

时间校验：镜头覆盖不漏不重；成片时长等于所含镜头预算；请求时长含余量且不超过本次上限；剪辑插镜不计入AI调用。节拍顺序连续；备用拆点避开身体翻转、接触压缩、物件悬空交接。计划时间不是已经测得的动作时长。

历史晨起示例在Seedance分组目录，schema_version 1原结构保留；现行示例为制作进度链接的“分镜与生成v2.1”，采用schema_version 2批次源。可运行以下只读校验；脚本只针对这种分组结构，其他场次拆分同一镜头时需明确coverage区间并调整校验，不能为了通过脚本强改叙事。

```powershell
python .agents/skills/linzhixia-production/scripts/validate_generation_plan.py --root . --plan 视频制作/本场生成分组/plan.json
```

它不发送生成请求，不验证模型画质或平台参数支持。实际工具须当次核对；模型或工具更换只改执行信息，不强迫资产图册、镜头ID全部重做。
